# 笔顺订正工作台（Flask + Canvas）

学生写出字形后，老师用尽量少的动作示范如何订正**笔顺**。在米字格画布上对着范字临摹，
系统按原始书写方向计算离散 Fréchet 距离来配笔，求出最少的 **移笔 / 删笔 / 补笔** 动作序列，
可逐步播放、可一键采纳“下一步移笔/删笔”并按实际笔序重算；支持标记必须保留的笔，
保留要求无法满足时给出“无解”。拖动配笔上限滑块时，画布旁即时预览每一档的最少步数或无解
（首次求解一次备好全部档位：每对笔画距离只算一次、候选相同的档位共用求解），
松手才生成与试算一致的正式方案。

## 用 Docker Compose 启动

```bash
docker compose up --build
```

然后打开：

- <http://localhost:8000>
- 或 <http://localhost:5000>（Compose 额外把宿主 5000 映射到容器 8000，兼容 Flask 默认端口习惯）

镜像用 gunicorn 跑 `app.server:app`，带 `/healthz` 健康检查。

## 本地直接运行

```bash
pip install -r requirements.txt
python run.py                 # 默认 0.0.0.0:8000，可用 PORT 覆盖
# 打开 http://127.0.0.1:8000
```

## 使用流程

1. 顶部选择范字（内置 **一 十 人 八 大 口 土 木**，均附标准笔序，见 `app/data/characters/`）。
2. 在米字格中按住拖动书写；最多 10 笔，前端会把每笔精简/等弧长重采样到 **≤64 点**，坐标统一到 **1000×1000 共用网格**。
3. 拖动右上角滑块设定 **离散 Fréchet 上限**（40–600，每 10 一档共 **57 档**，默认 180/1000 网格单位）。
   **首次点「求最优修订」或「填入示例笔迹」时，前端会一次备好全部 57 档的试算**：
   画布上方的试算条与滑块旁的胶囊会实时显示
   「上限 t：这一档最少要改 **N** 步（移 a · 删 b · 补 c）」或「这一档**无解**」。
4. 试算备好后，**来回拖动滑块不发任何请求**，数字全部来自本地试算。拖动期间
   **播放 / 上一步 / 下一步 / 采纳全部停用**（步骤列表也锁定），并提示
   「松开滑块生成正式方案」；**松手（change）才为所选档位请求一次正式方案**，
   返回后试算条给出「✓ 正式方案的动作数与可行性和试算一致」。
5. 正式方案显示最少动作总数与「移 / 删 / 补」计数，并列出每一步。
   （也可以不先求解、直接拖滑块：首次拖动会先请求 `/api/preview` 备档，松手再出正式方案。）
6. 用 **播放 / 上一步 / 下一步 / ⏮** 逐步观看：
   - 移笔：蓝色高亮 + `from → to` 标记，笔画顺序徽标重排（几何位置不变，变的是笔序）；
   - 删笔：红色残影提示后移除；
   - 补笔：对应范字笔画以**紫色虚线**（带流动动画）示意；求解后所有缺笔也会先以淡虚线标出。
7. 点 **采纳下一步：删除/移动…**，该动作真正作用于实写笔画，随后前端立即撤下旧试算/方案，
   **按当前实际笔序重新备档 + 求解**；右侧记录已采纳动作。可反复采纳直到只剩补笔示范。
8. 每行笔画有 **↑ / ↓** 按钮可直接手改笔序，另有 **保留** 勾选：保留笔不会被建议删除或移动
   （行内“删除”按钮也会禁用）。**换范字、写/撤销/删除笔迹、↑↓ 改笔序、勾选保留**都会
   **立即撤下旧试算与正式方案**（同步显示失效提示、停用采纳），并自动为新稿重新备档；
   保留要求无法满足时试算条与方案面板都给出 **无解** 与原因。
9. 旧稿/过期请求不会上屏：每份草稿带递增 token，草稿一变，在途的试算响应直接丢弃；
   重新拖动滑块会 `AbortController` 作废上一档在途的正式方案，只渲染最后所选档。
10. **准备或求解失败时笔迹原样保留**，试算条/方案面板出现中文错误与
    「重试准备 / 重试求解」按钮（也可再点「求最优修订」）。
11. 没有笔迹时可点 **填入示例笔迹（含典型错误）** 快速体验：「木」示例稳定为
    cost=3（移 1 · 删 1 · 补 1），拖到 40 档变为 8 步（4 删 + 4 补），50 档为 6 步，
    80 档起回到 3 步。

1. 顶部范字保持默认 **木**。点 **填入示例笔迹（含典型错误）**。
   - 画布出现 4 笔（顺序颠倒的两笔 + 正常笔 + 左上角多余涂鸦）。
   - 画布上方试算条先显示「各档试算准备中…」，随后变为绿色：
     **上限 180 档：这一档最少要改 3 步（移 1 · 删 1 · 补 1）**；
     右侧方案面板同步显示「最少 3 个动作」，步骤列表 3 行，
     试算条末尾出现「✓ 正式方案的动作数与可行性和试算一致」。
   - 此时后端日志只有 1 次 `POST /api/preview`（57 档）和 1 次 `POST /api/plan`。
2. **按住右上角滑块拖到最左端 40**（不松手/只触发 input）：
   - 无需等待，试算条立即变红/变数字：**最少要改 8 步（移 0 · 删 4 · 补 4）**，
     滑块旁胶囊显示「上限 40：最少 8 步…」；
   - **播放、▶、◀、⏮、采纳按钮全部变灰**，试算条提示「拖动预看中…」；
   - 继续在 40 / 50 / 80 / 180 之间来回拖：数字在 **8 / 6 / 3 / 3** 间即时切换，
     浏览器 Network 面板**没有新的 `/api/plan` 或 `/api/preview` 请求**。
3. 在 **50** 档松手：按钮短暂显示「求解中…」，随后方案面板变为最少 **6** 步，
   试算条出现一致性 ✓；再拖到 **180** 松手，方案回到 **3** 步。
   （可以快速做一次「拖到 600 松手 → 立刻又拖回 180」：在途的 600 档方案会被作废，
   最终上屏的一定是 180 档的 3 步。）
4. 演示无解：在「实写笔画」列表勾选第 4 笔（那笔远离范字的涂鸦）的 **保留**。
   - 旧试算/方案立刻撤下并出现黄色失效条、采纳禁用；新试算回来后试算条与红色面板都显示
     **无解**：「标记保留的第 4 笔与任何范字笔画的离散 Fréchet 距离都超过上限…」
     （该涂鸦在 180/600 档都配不上）。取消勾选即恢复 3 步。
   - 也可保留最前面两笔后把上限拖到 40：试算条立即显示该档无解。
5. 演示改笔序失效：点任意笔画行的 **↑ / ↓**，旧结果同步撤下并自动重新备档/求解。
6. 回到 180 档、取消所有保留，点绿色 **采纳下一步：删除第 4 笔**：
   - 红色残影播放删除，该行消失；右侧「已采纳动作」出现一条记录；
   - 页面自动重新备档/求解，最少动作 **3 → 2**（恰降 1），新按钮为
     「采纳下一步：移动第 2 笔 → 第 1 位」。
7. 再点一次采纳：蓝色移笔演示后笔序徽标重排，动作 **2 → 1**；
   此时采纳按钮禁用，面板提示「已无需移 / 删，请播放查看虚线补笔」，
   终态计数为 **移 0 · 删 0 · 补 1**，画布上紫色虚线补出缺失的中竖。
8. 点 **播放**（或 ▶ 单步）回看删 / 移 / 补动画；点 ⏮ 复位。
9. 失败重试演示（可选，需 DevTools）：Network 面板把 `/api/preview` 或 `/api/plan`

   试算条出现「重试准备」、方案面板出现「重试求解」；恢复网络后点重试即正常。

## 算法说明

### 配笔：按原方向的离散 Fréchet 距离

`app/core/frechet.py` 的 `discrete_frechet(P, Q)` 是标准 O(p·q) 动态规划，
从首点走到末点，**不反转**任何一条曲线，因此撇/捺、逆序笔画不会被当作同向。
只有 `distance ≤ threshold` 的“实写笔 × 范字笔”才进入兼容矩阵。服务端直接对收到的
≤64 点序列计算离散 Fréchet（点数量上限正好把 DP 限制在 64×64）。

### 滑块各档试算：距离一次、同候选档位共用求解

`app/core/planner.py` 的 `build_preview(strokes, model, thresholds)` 为整根滑块备档：

1. `dist[x][j] = discrete_frechet(...)` 双层循环**只跑一遍**，共 `K·N` 次距离计算
   （测试用 mock 计数断言恰好 `K·N` 次）；
2. 每档把 `dist` 阈值化为布尔兼容矩阵，并把该矩阵的不可变元组作为缓存键；
3. 键相同的档位（阈值落在相邻距离值之间时候选完全一致）直接复用同一个 `SolveResult`，
   **只做一次 `solve_matrix`**；返回的 `solve_count` 即去重后的矩阵数，
   测试独立从 `dist` 重算不同矩阵个数并断言相等；
4. 每档输出与正式方案同口径的 `feasible / cost / counts / reason`。

8 个范字的错误示例 × 57 档实测：`solve_count` 仅 **1（一）/5（十、人、八）/6（大、口）/
8（土）/10（木）**，其余档位全部命中共享结果。

### 最少动作：带“不动主干（backbone）”的掩码 DP

范字有 `N` 个笔序槽位，成稿与范字**按笔序一一对应**：每个槽位要么放一笔兼容的实写笔，
要么记一次补笔；没被使用的实写笔记一次删笔。

- 一次“移到任意笔序位置”收费 1。
- 相对顺序与目标槽位一致的若干实写笔可以**不动**，构成递增主干；其余被使用的笔每笔移动一次。
- 对一个确定的配笔方案，最少移笔数 = 使用笔数 − 包含全部保留笔的最长递增子序列长度。

DP（`app/core/planner.py`）按实写当前顺序逐笔处理，状态为
`(最后一条主干槽位 last, 已占用范字槽位掩码 mask)`，每笔三选一：

| 选择 | 代价 | 约束 |
| --- | --- | --- |
| 删除 | 1 | 保留笔禁止 |
| 移动使用 `mv(j)` | 1 | `j` 兼容且未被占用；不约束主干顺序；保留笔禁止 |
| 不动/主干 `bb(j)` | 0 | `j > last`、兼容、未占用 |

结尾对每个未占用槽位加 1 次补笔。`N,K ≤ 10`，掩码仅 `2^10`。
保留笔被强制走 `bb`：既不能删也不能移动；若 DP 无可达终态即 **无解**，
并区分“保留笔无兼容范字笔画”和“保留笔顺序冲突”两种中文原因。

### 可播放步骤与“下一步”

由最优决策先产出删除步，再对剩余笔重算“含全部保留笔的最大强制 LIS”作为固定主干，
用确定性的插入构造 `move_operations_to_target`（已用穷举 1..8 全排列 + 随机用例验证：
每次都恰好得到目标顺序、每个移动笔只动一次且无空操作）。移动/删除步的 `from/to/index`
与前端 `applyMove`（先 `splice(from,1)` 再插入结果下标 `to`）严格同一语义，
因此预览逐步应用与老师采纳完全一致。每个“下一步”都经性质测试验证：采纳后重新求解的最优值
**恰好下降 1**。补笔步直接携带范字点列供虚线绘制。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 画布页面 |
| GET | `/healthz` | 健康检查 |
| GET | `/api/characters` | 范字清单 |
| GET | `/api/characters/<id>` | 某范字完整笔画点列 |
| GET | `/api/sample/<id>` | 确定性错误示例（供“填入示例”/测试） |
| POST | `/api/preview` | **一次备好滑块各档试算**（别名 `/api/trials`、`/api/prepare`） |
| POST | `/api/plan` | 求所选档位的正式修订方案（含可播放步骤） |

`POST /api/preview`：

```json
{
  "character_id": "mu",
  "thresholds": [40, 50, 60],
  "strokes": [ {"uid": "s0", "preserved": false, "points": [[500, 395], "..."]} ]
}
```

- 省略 `thresholds` 时使用与滑块一致的默认 57 档（40–600，步长 10）；最多 200 档。
- 服务端对**每对实写笔 × 范字笔的原方向离散 Fréchet 距离只计算一次**（`dist` 矩阵随响应返回），
  之后每档只做一次阈值比较得到兼容矩阵；**兼容矩阵逐格完全相同的档位共用同一次 DP 求解**。
- 返回 `levels[]`，每档形如
  `{threshold, feasible, cost, counts{move,delete,add}, reason}`，
  以及 `level_count / solve_count / pair_count`（57 档在示例上实际只做 1–10 次求解，见下）。
- 同一草稿、同一档位，`/api/preview` 的试算结论与 `/api/plan` 的
  `feasible / cost / counts` 由同一个 `solve_matrix` 产出，严格一致；
  `tests/test_preview.py` 对 8 个范字 × 全部 57 档逐一比对了这一点。

`POST /api/plan`：

```json
{
  "character_id": "mu",
  "threshold": 180,
  "strokes": [
    {"uid": "s0", "preserved": false, "points": [[500, 395], "..."]}
  ]
}
```

也可用 `"model": [[[x,y], ...]]` 直接内联范字。返回 `feasible / reason / cost /
counts{move,delete,add} / steps[] / next_action / compatible / dist / assign` 等。
超出“≤10 笔 / 每笔≤64 点”等限制时返回 `feasible:false` 与中文原因。
